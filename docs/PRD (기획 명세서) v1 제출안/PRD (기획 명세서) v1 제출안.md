## 1. 프로젝트 목표

트리플에 이미 입력된 **여행 일정 데이터(목적지·기간·동반유형·활동)를 활용해 준비물 체크리스트를 자동 생성**함으로써,

1. **사용자 관점** — 사용자가 스스로 떠올리지 못한 항목까지 포함된 리스트를 받아, 준비물 누락과 과잉 준비를 동시에 줄인다.
2. **서비스 관점** — 계획(Planning) 단계에서 끝나던 트리플의 사용 주기를 **출발 직전(D-3~D-day)까지 연장**해 재방문 접점을 확보한다.
3. **비즈니스 관점** — '구매 필요' 항목의 구매 의사 시그널을 수집해, 부가 수익 경로의 성립 가능성을 판단할 근거를 확보한다.

## 2. 프로젝트 배경

#### 여행 도메인 시장 현황

- 2026년 내국인 해외여행객 약 **3,023만 명** 전망(역대 최대). 다만 고환율 영향으로 증가세는 둔화 중(1월 +12.2% → 3월 -1.7%)
- 글로벌 여행·관광 산업의 GDP 기여액은 2025년 **11.6조 달러**로 역대 최고치를 기록하며 성장 국면 지속

#### 여정 단계별 경쟁 강도 — 왜 'Pre-trip'인가

성장하는 여행 시장을 여정 단계별로 뜯어보면 경쟁 강도가 매우 불균형하게 분포되어 있다.

| 여정 단계 | 주요 플레이어 | 경쟁 강도 |
| --- | --- | --- |
| Inspiration (어디로 갈까) | SNS·유튜브 | 높음 (장악) |
| Planning (일정·동선) | 트리플, 마이리얼트립, 각종 AI 플래너 | 매우 높음 |
| Booking (항공·숙소·액티비티) | OTA 전반 | 포화 |
| **Pre-trip (짐·서류·환전·규정)** | **뚜렷한 대표 서비스 없음** | **낮음 (공백)** |
| In-trip (현지 실행·돌발 대응) | 부분적 | 낮음 |

준비(Pre-trip) 단계는 **독점적 대표 서비스가 없고, 커머스와의 연계도 미흡**하다. 시장 규모 자체는 작지만, 이미 여행 일정 데이터를 보유한 플랫폼이 진입하면 낮은 비용으로 선점 가능한 영역이라고 판단했다.

#### 트리플 현황

- **연혁**: 2020년 야놀자 인수 → 2022년 인터파크와 합병(인터파크트리플) → 놀유니버스 통합 플랫폼 **'NOL'** 출범 후 결합 예정
- **자기 정의**: "나를 아는 여행 앱" — 예약부터 일정까지 여행을 더 쉽게
- **핵심 방향성**: **초개인화**. 900만 명 이상의 누적 이용자와 여행 빅데이터를 AI와 결합해 "개인 비서처럼" 여행을 돕겠다는 전략
- **2025년 홈 리뉴얼**: 숏폼 '스토리' 신설, 관광지 중심 → **경험 중심** 여행 트렌드 반영, 도시 추천 정교화. "지금 나에게 가장 맞는 여행을 빠르고 직관적으로 발견"하는 것이 개편 목표
- **차별점**: 일반 여행 앱이 '상품 판매'를 위해 존재하는 것과 달리, 트리플은 **여행 전 계획 → 여행 중 현지 정보 → 여행 후 후기까지 전 과정**을 다룸
- **유저 구성**: 전체 이용자의 **73%가 2030 세대**
- **향후 전망**: 채용 공고 기준 일본·대만 등 글로벌 서비스 준비 중

**현재 수익 경로(추정)**: 항공권 실시간 예약 / 해외 숙소 예약(최저가·상시 쿠폰) / 투어·티켓·액티비티 / **셀프 패키지**(항공+숙소+투어 조합, 많이 살수록 혜택 확대)

**AARRR 흐름(현재)**: 앱 유입 → 여행 일정 만들기 → 셀프 패키지 구성 → 결제 → 여행 후기 작성

> **본 프로젝트의 전략적 위치**: 트리플이 이미 확보한 '일정 데이터'를 준비물 영역에 재사용해, 경쟁이 비어 있는 Pre-trip 구간을 초개인화 전략의 연장선상에서 선점한다.

## 3. 문제 현상

### 3-1. 발견한 문제 상황

<aside>

**A. 짐(준비물) 관련 문제**

1. **준비물 누락** — 국가 불문 반복적으로 필수품을 빠뜨림
2. **누락에 대한 불안감** — 실제 누락 여부와 무관하게 짐 싸는 과정 자체에서 느끼는 스트레스
3. **과잉 짐싸기** — "혹시 몰라서" 다 챙기다가 무게·부피 부담, 불필요한 구매로 이어짐
4. **유형별 니즈 차이** — 과다포장형 / 미니멀리스트형 / 벼락치기형 등 짐싸기 유형에 따라 필요한 도움이 다름
</aside>

<aside>

**B. 정보 탐색의 어려움 (탐색 과정 자체의 문제)**

1. **탐색 비용** — 블로그·유튜브 등에서 정보를 찾아야 하는데 정리·관리 기능은 없음
2. **광고성 정보 과다** — 광고가 교묘히 섞여 있어 정보 신뢰도가 낮음
3. **잦은 규정 변경** — 보조배터리 등 기내 반입/위탁 규정이 자주 바뀌어 최신 정보 파악이 어려움
</aside>

<aside>

**C. 정보의 분산·공백 (탐색 결과의 구조적 문제)**

1. **정보 채널 분산** — 환전·날씨·교통편·준비물 정보를 각각 다른 채널에서 따로 찾아야 해 피로도 증가
2. **현지 교통편 정보 부재** — 항공권은 예약되지만 현지 이동 수단 정보는 별도 탐색 필요
</aside>

<aside>

**D. 환전·예산 관리 문제**

1. **선불카드 충전 한도 초과** — 이중환전 회피 목적의 선불카드 충전 한도(약 300만 원) 초과 시 결제 불가
2. **환전 정보 반복 탐색** — 환율·환전 방법 정보를 매번 직접 검색해야 함
3. **예산 초과** — 선물 예상 금액 등 누락 항목으로 인한 상시적 예산 초과
</aside>

→ 상위 사유는 두 갈래다. **'독립 앱이라서' 생기는 마찰**(59.6%, 50.0%)과 **'메모장이 더 빠르다'는 사용 편의**(53.8%)이며, 리스트 품질 불신(26.9%)보다 크다. 앞의 마찰은 이미 설치·로그인되어 있고 여행 일정까지 들어 있는 트리플 안에서 구조적으로 사라진다.

다만 마찰 제거만으로는 충분하지 않다. 트리플에는 이미 정적 체크리스트가 존재하지만 이를 인지한 응답자는 **3.8%(2명)** 에 불과했다. 마찰이 없는 조건에서도 쓰이지 않고 있다는 뜻이며, 이는 두 가지를 함께 풀어야 함을 가리킨다.

**② 셀프 체크리스트의 구조적 한계 — "모르는 건 못 적는다"**

- 체크리스트를 만들어본 경험: **74.5%**(41/55) — 그중 **97.6%가 메모앱·노트에 직접 작성** (전용 앱 이용 0명)
- 그런데도 **매번 꼼꼼히 작성하는 사람의 36.4%가 여전히 물건을 빠뜨림** (체크리스트를 안 만드는 사람은 25.5%, 가끔 만드는 사람은 38.2%)

| 구분 | 빠뜨린 경험 |
| --- | --- |
| 체크리스트를 매번 작성 (n=20) | 36.4% |
| 체크리스트를 가끔 만듦 (n=21) | 38.2% |
| 체크리스트를 안 만듦 (n=14) | 25.5% |

주관식 응답(반복 패턴):

> "내가 생각해내지 못한 물건은 파악할 수 없다"
"내가 놓친 게 있는지 검토할 수 없음"
"리스트업이 완전한지 불안하다"
> 

→ 체크리스트라는 틀(도구)은 이미 쓰고 있지만, 그 내용이 결국 **자기 기억**에서만 나오기 때문에 완전성을 검증할 방법이 없다는 것을 정량·정성 데이터가 동시에 뒷받침한다.

**③ 낭비는 양방향으로 발생한다**

| 항목 | 비율 |
| --- | --- |
| 챙겼는데 한 번도 안 쓴 물건 1개 이상 | **81.8%** |
| 여행지에서 준비물을 급하게 구매한 경험 | **58.2%** |
| 빠뜨린 물건이 있었음 | 47.3% (기억 안 남 포함 시 54.6%) |
- 급구매 지출액(n=32): 1~3만원 62.5%, 1만원 미만 25% → **1인당 평균 약 1.5만원 내외의 불필요한 지출**
- **급구매 경험(58.2%)이 빠뜨림 인지(47.3%)보다 많다** → "빠뜨린 줄도 몰랐던" 채로 현지에서 사는 경우가 존재 (애초에 필요한 줄 몰랐던 물건들)
- **급구매(58.2%)가 빠뜨림 인지(47.3%)보다 응답 수 기준 6명 많다.** 두 응답이 최대로 겹친다고 가정해도 **최소 6명(급구매자의 18.8%)은 "빠뜨린 건 없는데 현지에서 급하게 산" 경우**에 해당한다 
→ 문제는 망각(빠뜨림)만이 아니라 **판단(무엇을 챙길지 미리 알기 어려움)** 에서도 발생한다.

#### 경쟁 서비스/기능 분석 결론

1. **개인화된 준비물 추천 + 일정 데이터 연동**을 동시에 가진 서비스는 없다. 전문 앱은 일정을 모르고, 여행 플랫폼은 개인화를 하지 않는다.
2. 전문 앱의 최대 약점은 기능이 아니라 **획득과 빈도**이다. 트리플은 이 지점에서 구조적 우위를 갖는다.
3. **구매 연결을 구현한 곳은 한 곳도 없다.** 이러한 공백의 원인은 객단가·빈도·리드타임·획득비용 네 가지다. 트리플은 **획득과 빈도가 이미 확보되어 있고** 리드타임은 푸시 알림 등 극복할 수 있는 방법이 있어 남는 제약은 객단가뿐이다. 이마저도 
① 사용자가 '준비물이 없음'을 표시한 뒤 제시하기 때문에 전환 가능성이 높고 
② 한 번에 여러 항목이 담겨 금액이 커지며 
③ 후기·사용 데이터를 활용해 근거 있는 추천을 할 수 있다는 점에서 완화할 수 있다고 분석했다.

### 4-3. 핵심 문제 정의

<aside>

사용자는 여행 맥락(국가·기간·장소·날씨·동반자 등)에 따라 필요한 물품을 스스로 파악해 짐을 챙기지만, 완전하게 챙겼는지 검증할 방법이 없어 무엇을 빠뜨렸는지 알 수 없다. 그 결과 **준비물을 누락하거나 과잉으로 챙기게 되고**, 현지에서 급하게 구매하느라 **불필요한 지출을 하거나 쓰지 않을 짐을 그대로 이고 다니게 된다**.

## 5. 가설

<aside>

여행 맥락(국가·기간·장소·날씨·동반자 등)을 기반으로 필요한 물품을 맞춤형 체크리스트 형태로 제공하면, 사용자가 준비·누락 여부를 확인할 수 있어 **준비물 누락과 과잉 준비가 감소**할 것이다.

</aside>

### 근거

**1. 체크리스트라는 ‘형식‘은 이미 효과가 있다 — 문제는 ‘내용’이다**

체크리스트를 매번 작성하는 사람도 35%는 빠뜨리지만, 안 만드는 사람은 57.1% 가 빠뜨린다. 형식 자체의 효과 차이는 이미 검증됐고, 남은 문제는 “메모앱은 자기 기억에서만 채워진다“는 정보원의 한계이다.

> → 즉 **누군가 대신 채워주는 맞춤 체크리스트**라면 이 한계를 그대로 메울 수 있다.
> 

**2. 사용자가 실제로 막막해하는 정보가 트리플이 이미 갖고 있는 데이터와 정확히 겹친다**

가장 알기 어려운 정보 1~4위(현지구매 나은 것 50.9%, 날씨별 옷차림 43.6%, 지역 특수 준비물 41.8%, 숙소 비치품 41.8%)는 전부 목적지·기간·날씨 같은 맥락 정보다.

> → 트리플은 이미 목적지·기간·동반유형·활동 데이터를 갖고 있으니, 자동 생성이 실제 페인포인트와 어긋나지 않는다. (“○○여행준비물” 검색 패턴도 이를 행동적으로 뒷받침)
> 

**3. 전용 앱이라는 대안은 이미 있지만 채택 장벽 때문에 실패했고, 그 장벽은 트리플 안에서 사라진다**

전용 앱 사용률은 0%에 불과한데, 이유는 기능 부족이 아니라 설치 마찰·계정생성 번거로움(50%)이었다. 경쟁 매트릭스에서도 “개인화 추천 + 일정 데이터 연동“을 동시에 가진 서비스는 없다.

> → 이미 설치·로그인돼 있고 일정 데이터도 있는 트리플 안이라면 이 마찰이 제거된 채로 같은 기능을 제공할 수 있다.
>

## 7. 기대효과 및 로드맵

### 7-1. 기대효과

**사용자 관점**

- 여행 맥락에 맞는 준비물을 스스로 검증할 수 있게 되어, 준비물 누락으로 인한 현지 재구매 지출(설문 기준 1인당 평균 1~3만원대)과 과잉 포장으로 인한 불편이 줄어든다.
- 메모앱에 흩어져 있던 습관을 트리플 안으로 옮겨오면서, 새 앱 설치 없이 기존 여행 준비 흐름 안에서 문제를 해결한다.

**비즈니스 관점**

- 트리플의 이용 경험이 예약·일정 단계에서 준비(Pre-trip) 단계까지 확장되어, 앱 체류 시간과 재방문 빈도(D-3~D-1 재방문)가 늘어난다.
- 준비(Pre-trip) 단계는 경쟁이 적은 영역이므로, 초개인화 체크리스트를 선점하면 트리플의 "나를 아는 여행 앱" 포지셔닝을 강화하는 데 기여한다.
- 목적지·시기·동반유형·여행활동별로 "실제로 무엇을 챙기는가"라는 행동 데이터가 집계 형태로 축적된다. 사용자가 추가한 항목은 초기 룰이 놓친 준비물이고 삭제한 항목은 과잉 추천이므로, 쓰일수록 추천이 정교해지는 동시에 어느 경쟁 서비스도 보유하지 못한 준비물 수요 데이터가 남는다.

### 7-2. 향후 로드맵

#### MVP 이후 확장

**목표**: 준비물을 넘어 Pre-trip 전반으로

- 여행 일정에 특화된 준비물 리스트 제공(데이터 기반 추천 정교화) - ex) 예약된 숙소의 비치 품목을 반영해 "챙기지 않아도 되는 항목" 자동 제외
- 한 줄 후기 / 준비물 추천 데이터 축적 → 커뮤니티 요소
- 여행 실무 정보 결합 검토: eSIM 사용법, 환전 정보, 캐리어 사이즈 가이드
- 글로벌 대응 — 대상 국가 확장 및 다국어 반영
- 콜드스타트 해소 — 프리셋 7개국 외 목적지를 기후대·권역 단위로 매핑
- 실시간 날씨 API 연동

- In-trip 구간 확장 — 현지 분실 방지, 귀국 시 짐 체크
- NOL 통합 플랫폼 내 준비물 모듈로의 이관
- **준비물 데이터 기반 커머스 큐레이션 고도화**
- 짐싸기 유형별(과다포장형/미니멀형) 리스트 강도 조절 — UT에서 유형별 반응 차이가 확인될 경우 승격

        출처: [https://linkrunner.io/blog/top-10-mobile-app-onboarding-metrics-that-predict-long-term-retention](https://linkrunner.io/blog/top-10-mobile-app-onboarding-metrics-that-predict-long-term-retention)
        
- **일자별 재방문율 (D-1 35~45%, D-3 20~25%, D-7 10~15%)**
    - 우수한 온보딩을 갖춘 앱의 Day-1 재방문율은 40~60%, 부실한 온보딩은 25% 미만으로 나타남. 반면 일반 앱의 Day-7 재방문율은 iOS 6.9%, Android 5.2% 수준으로 급격히 하락하는 것이 표준 패턴임.
        
        출처(Day-1 벤치마크): [https://www.dots-mobile.com/blog-posts/mobile-app-onboarding-best-practices](https://www.dots-mobile.com/blog-posts/mobile-app-onboarding-best-practices)
        출처(Day-7 벤치마크): [https://scandiweb.com/blog/user-onboarding-best-practices/](https://scandiweb.com/blog/user-onboarding-best-practices/)
        
    - 본 서비스는 출발일이 임박할수록 확인 유인이 커지는 여행 준비 앱 특성상, 일반 앱 대비 재방문 곡선이 완만하게 유지될 가능성이 높다고 판단하여 D-7 구간을 일반 벤치마크 대비 상향(10~15%) 조정하였고, D-1은 긴급성이 최대인 구간으로 판단하여 Day-1 벤치마크 하단부를 채택함.
- **checklist_page_exit 가드레일 (40% 이하)**
    - 앱 설치 후 3일 내 77%가 이탈하는 것이 일반적 패턴으로 보고되나, 이는 "설치 후 이탈"로 페이지 단위 이탈률과 성격이 상이함. 이에 웹 표준 바운스레이트(40~60%) 기준을 참고하여 그보다 낮은 40% 이하를 가드레일로 설정함. 초과 시 UX 결함 조사 트리거로 활용 권장.
        
        출처: [https://scandiweb.com/blog/user-onboarding-best-practices/](https://scandiweb.com/blog/user-onboarding-best-practices/)
